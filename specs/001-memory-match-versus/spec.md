# Feature Specification: 神経衰弱 対戦ゲーム

**Feature Branch**: `001-memory-match-versus`
**Created**: 2026-11-24
**Status**: Draft(人間のレビュー待ち)
**Input**: 神経衰弱を作る。ペアでカードを取得でき、二人以上(CPU戦を含む)で対戦できること。決定事項は `interview.md` を参照。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 2人で対戦する (Priority: P1)

プレイヤーとして、同じPCでもう1人と交互にカードをめくり、ペアを取り合いたい。

**Why this priority**: 「二人以上で対戦」「ペアで取得」という課題の必須条件そのもの。

**Independent Test**: 2人対戦モードを開始し、決まった配置で成立・外れ・手番交代・得点を順に確認する。

**Acceptance Scenarios**:

1. **AS-01 (初期状態)** **Given** 2人対戦を開始した直後、**Then** 20枚すべてが裏向き。両者の取得ペア0・得点0。プレイヤー1の手番。クリアや終了は表示されない。
2. **AS-02 (めくる)** **Given** プレイヤー1の手番、**When** 矢印キーでカーソルを動かしSpaceを押す、**Then** カーソル位置の1枚が表になる。1回の手番で続けて2枚までめくれ、3枚目はめくれない。
3. **AS-03 (成立)** **Given** 2枚をめくり同じ絵柄、**Then** その2枚は表のまま取得される。取得者の得点が「取る直前の残りペア数×10」点増える。手番は交代せず、同じプレイヤーがもう一度めくれる。
4. **AS-04 (外れ)** **Given** 2枚をめくり違う絵柄、**Then** 判定は2枚目をめくった時点で確定する。2枚は約1秒表のまま見える。その間はすべての入力を受け付けない。1秒後に2枚とも裏に戻り、手番が相手に交代する。得点の増減はない。
5. **AS-05 (二重防止)** **Given** 取得済みのカード、または今の手番で表になっているカード、**When** Spaceを押す、**Then** 何も起きない(同じカードを2枚目に選ぶこともできない)。

---

### User Story 2 - CPUと対戦する (Priority: P1)

プレイヤーとして、1人でもCPUを相手に対戦したい。

**Why this priority**: 「CPU戦を含む」が必須条件。

**Independent Test**: CPU戦を開始し、CPUの手番で人間の入力が無視されること、CPUが自分でめくって判定されることを確認する。

**Acceptance Scenarios**:

1. **AS-06 (CPU手番)** **Given** CPU戦でCPUの手番、**Then** CPUが自動で2枚をめくる。この間、人間のキー入力(カーソル移動・Space)は無視される。判定・得点・手番交代はAS-03〜AS-04と同じ。
2. **AS-07 (CPUの記憶)** **Given** CPUが過去に絵柄を見たカードが盤面にある、**Then** CPUは各カードを70%の確率で覚えている。覚えている絵柄のペアが揃うなら、そのペアを狙う。覚えていなければ未確認のカードをめくる。
3. **AS-08 (再現性)** **Given** 乱数シードを指定して開始、**Then** 同じシードなら配置とCPUの選択が毎回同じになる。

---

### User Story 3 - 勝敗が決まる (Priority: P2)

プレイヤーとして、全ペアが取られたら結果(勝ち・負け・引き分け)を見たい。

**Why this priority**: 対戦として完結させるため。

**Independent Test**: 全10ペアを取らせて、得点比較の結果表示と以後の入力停止を確認する。

**Acceptance Scenarios**:

1. **AS-09 (勝敗)** **Given** 全10ペアが取得された、**Then** 得点が高いプレイヤーの勝ちを表示する。同点なら引き分けを表示する。
2. **AS-10 (終了後)** **Given** 結果表示中、**When** カーソル移動やSpaceを押す、**Then** 何も起きない。受け付けるのは 1・2・R だけ。
3. **AS-11 (得点の例)** **Given** 序盤の1組目(残り10ペア)を取る、**Then** +100点。最後の10組目(残り1ペア)なら+10点。全ペアを1人が取ると合計550点。

---

### User Story 4 - モード選択と再開 (Priority: P2)

プレイヤーとして、モードを選んで始め、いつでもやり直したい。

**Why this priority**: 検証と繰り返しの遊びに必要。

**Independent Test**: 起動直後・対戦中・終了後のそれぞれでキーを押し、状態が初期化されることを確認する。

**Acceptance Scenarios**:

1. **AS-12 (起動直後)** **Given** 起動直後、**Then** タイトル画面が表示され、盤面は表示されない。**When** 1キー、または「2 Players」ボタンの操作をする、**Then** 2人対戦が始まる。2キー、または「vs CPU」ボタンの操作ならCPU戦が始まる(AS-15)。
2. **AS-13 (再開)** **Given** 対戦中または終了後、**When** Rを押す、**Then** 現在のモードで、配置をシャッフルし直して初期状態(AS-01)に戻る。得点と取得数も0に戻る(表示だけを戻すのではない)。
3. **AS-14 (モード切替)** **Given** 対戦中または終了後、**When** 1または2を押す、**Then** そのモードで新しいゲームが始まる。

---

### User Story 5 - タイトル画面とマウス操作 (Priority: P2) *(2026-11-24 追加)*

プレイヤーとして、タイトル画面でモードを選び、キーボードでもマウスでも操作したい。

**Why this priority**: 実機でキーボードだけでは操作しづらい、との要望。モード選択を分かりやすくする。

**Independent Test**: タイトル画面でボタンを押してモードを選び、盤面のカードをマウスでクリックしてめくる。対戦中に「Title」で戻る。

**Acceptance Scenarios**:

1. **AS-15 (タイトル)** **Given** 起動直後またはタイトルに戻った直後、**Then** ゲーム名、「2 Players」ボタン、「vs CPU」ボタンを表示する。盤面とスコアは表示しない。上下キーで選択、SpaceまたはEnterで決定、1・2キー、マウスクリックのどれでもモードを選べる。
2. **AS-16 (カードをクリック)** **Given** 人間の手番、**When** カードをマウスでクリックする、**Then** キーボードのSpaceと同じ規則でそのカードがめくれる(取得済み・表向き・保留中・CPUの手番・終了後は無視される)。
3. **AS-17 (画面のボタン)** **Given** ゲーム中、**Then** 「Restart」と「Title」ボタンが表示される。Restartは現在のモードの再開(AS-13と同じ)、Titleはタイトル画面に戻る。キーボードのRとEscも同じ動作をする。保留中は無視される。

### Edge Cases

- 1枚目をめくった後、外れ表示中(約1秒)に入力しても何も起きない。
- CPU戦でCPUが成立させたら、CPUがもう一度めくる(AS-03と同じ)。
- 20枚すべてが取得された最後の判定で、手番交代の表示は出さず結果表示に移る。
- 点数が同じなら引き分け(先攻・後攻での決着はしない)。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 2人対戦モードを提供する。人間2人が同じキーボードで交互に操作する。
- **FR-002**: CPU戦モードを提供する。人間1人(プレイヤー1)対 CPU(プレイヤー2)とする。
- **FR-003**: 盤面は20枚(10ペア)、5列×4行とする。各絵柄がちょうど2枚ずつ配置される。
- **FR-004**: 起動直後はタイトル画面とし、タイトル画面からモード(2人対戦/CPU戦)を選んで開始する。選び方は、1・2キー、上下キー+Space/Enter、マウスクリックのどれでもよい。
- **FR-015**: 人間の手番では、カードをマウスでクリックしてめくれる。規則はキーボードのSpaceと同じ(FR-005、FR-012)。
- **FR-016**: ゲーム中に「Restart」「Title」ボタンを表示する。Escキーでタイトル画面に戻る。保留中(FR-006)は入力を受け付けない。
- **FR-005**: 矢印キーでカーソルを動かし、Spaceで1枚めくる。1回の手番では、成立するまで1回に2枚までめくれる。
- **FR-006**: 2枚目をめくった時点で判定を確定する。外れた2枚は約1秒表示し、その間は入力を受け付けず、その後に裏へ戻す。
- **FR-007**: 成立したら同じプレイヤーが続けてめくる。外れたら相手に手番を渡す。
- **FR-008**: 成立で取得者に「取る直前の残りペア数×10」点を加える。外れで得点は変わらない。
- **FR-009**: 取得したペア数と得点を、プレイヤーごとに表示する。現在の手番も表示する。
- **FR-010**: 全ペアが取得されたら得点を比較し、勝者または引き分けを表示する。以後は1・2・R以外を受け付けない。
- **FR-011**: CPUは、見た絵柄のカードを70%の確率で覚える。覚えている絵柄で成立できる場合は狙い、そうでなければ未確認のカードをめくる。CPUの手番中は人間の入力を受け付けない。
- **FR-012**: 取得済みのカード、表向きのカード、同じカードの再選択はできない。
- **FR-013**: Rで現在のモードを、配置をシャッフルし直して初期状態から再開する。
- **FR-014**: 乱数シードを指定して開始でき、同じシードなら配置とCPUの選択が再現される。

### Key Entities

- **カード**: 絵柄(10種類)、表裏、取得済みかどうか。20枚で、絵柄ごとに2枚。
- **プレイヤー**: 種別(人間/CPU)、取得ペア数、得点。
- **ゲーム状態**: モード、手番のプレイヤー、めくった枚数、残りペア数、結果(進行中/勝ち/引き分け)。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: AS-01〜AS-17 のすべてが、テストと実際のプレイで合格する。
- **SC-002**: 同じシードで開始すると、配置とCPUの選択が2回とも一致する。
- **SC-003**: 全ペアを取得した時点で、両者の得点の合計が、取得されたペアの点数の合計と一致する。
- **SC-004**: 1ゲーム(全10ペア)を、人間2人でもCPU戦でも最後までプレイできる。
- **SC-005**: Rで再開した後に、全カード裏向き、取得0、得点0になっている。

## Assumptions

- 先攻はプレイヤー1。CPU戦では人間がプレイヤー1。
- 絵柄は色と記号で区別し、外部アセットは使わない。
- 範囲外: 効果音、オンライン対戦、ランキング、3人以上の対戦、CPUの強さの選択、実行ファイルのビルド。
- [NEEDS CLARIFICATION] なし。残りの細部(外れ表示の1秒の厳密な値など)は Plan で決める。
