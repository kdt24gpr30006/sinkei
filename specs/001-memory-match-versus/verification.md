# Verification: 神経衰弱 対戦ゲーム

検証日: 2026-11-24 / Unity 6000.6.7f1 / unity-cli 0.19.1 / シード 12345 / シーン `MemoryMatch.unity`

## 方法

- **状態の根拠**: `unity-cli raw get_component_values` で `Game` の `MemoryGameController` を読む(モード、手番、得点、取得数、残りペア、保留、`cardStates`、`visibleSymbols`)。
- **画面の根拠**: `capture_screenshot`(Game View)の画像を、画像ファイルを開いて目で読んだ。
- **操作**: Play 中に、Input System のキーボードへ入力イベント(Digit1/2、R、Space、矢印)を送った。
- **やっていないこと**: ゲーム状態の直接書き換え、裏向きのカードの絵柄を読む操作(`visibleSymbols` は表向きのカードだけを返す)。AI は、表になって見えた絵柄だけを記憶して打った。
- **ログ**: `evidence/play-log-2p.txt`(2人対戦、全10ペア)、`evidence/play-log-cpu.txt`(CPU戦、全10ペア)。

### 環境で実際に起きたこと(正直な記録)

1. ブリッジの `input_keyboard` コマンドは成功を返したが、ゲームがキー入力を受け取らなかった(`Keyboard.current` に状態が反映されず、`onAfterUpdate` にも届かなかった)。原因は特定していない。代わりに `unity-cli editor eval` から `InputSystem.QueueStateEvent` で同じ仮想キーボードへ入力イベントを送った。ゲームのコードは通常の `Keyboard.current` 経由で読んでいる。
2. Unity ウィンドウが背景にあるとPlayのフレームが進まなかった(`Time.frameCount` が 2 で停止)。Play 中だけ `Application.runInBackground = true` を設定した(プロジェクト設定のファイルは変更していない)。
3. `modify_component` で、待ち時間の設定 `mismatchDelay` と `cpuDelay` を一時的に変えた(AS-04 は 15 秒、AS-06 は 30 秒)。CLI の呼び出し間隔が長く、1秒の窓では「入力が無視されること」を確かめられなかったため。ゲームの状態(得点・カード)は書き換えていない。通しプレイでは `mismatchDelay=1.0`、`cpuDelay=0.6` に戻して実行した。

### AS-03 / AS-11 の得点の照合(ログから機械的に計算)

2人対戦 `play-log-2p.txt`: 各組で「直前の残りペア数×10」と実際の増分が一致(10組すべて ok)。取得者は、プレイヤー2が100・90・80・70・60・50、プレイヤー1が40・30・20・10。合計 450 + 100 = 550。

CPU戦 `play-log-cpu.txt`: 1行で複数ペアが増える箇所があり、機械的な照合では1件が不一致と出たが、これは最後の4ペア(40+30+20+10=100)がログの1行にまとまっただけで、最終得点 450 + 100 = 550 は一致。

## 未成立・未確認・注意

- **未成立(引き分け)**: 点数が「残りペア数×10」で10ペアの場合、合計は常に550点で、2人の得点は10の倍数。275点ずつにならないため、実プレイで引き分けは起きない。判定そのものは `MemoryGame.Decide(275, 275) == Draw` の単体テストで確認した。SPECは変更していない(承認済み、`analysis.md` 参照)。
- **未確認**: 終了後の1・2キー、起動直後の2キー、CPU戦でのR、CPU戦での取得済みカードの再選択。
- **注意(CPU戦の結果)**: この通しプレイでは、人間側のAIが、CPUの手番でめくられたカードを見ていないため弱く、CPUが10ペアすべてを取った。CPUが裏のカードを覗いていないことは、コード(`CpuBrain` は `VisibleSymbol` と観察した記憶だけを使う)で確認した。強さの評価は行っていない。
- **注意(見た目)**: 結果の文字とヒントの文字が画面下で近い(読める)。
